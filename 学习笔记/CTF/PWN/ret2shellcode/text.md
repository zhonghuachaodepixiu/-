# ret2shellcode

## 一、什么是 Ret2shellcode
- `Ret2shellcode`（`Return to shellcode`）是指利用栈溢出漏洞，将一段用于获取 `shell` 的机器码（`shellcode`）写入到可执行的内存区域（通常是栈上），然后通过覆盖返回地址（`EIP`/`RIP`），让程序跳转到该 `shellcode` 的起始地址去执行，从而拿到目标主机的控制权。

## 二、利用前提（极其重要）
1. 程序必须关闭 `NX` 保护（**No-eXecute**）： 即栈内存必须是“可读可写可执行”的（`RWX`）。如果开了 `NX`，你写进去的 `shellcode` 只能被当成普通数据，程序一执行就会报段错误（**SEGFAULT**）。
2. 必须知道 `shellcode` 在内存中的绝对地址： 你覆盖返回地址时，必须精准指向你写入 `shellcode` 的那个内存地址。如果开启了 `ASLR`（地址随机化），通常还需要配合一个“**信息泄露**（`Info Leak`）”漏洞来获取地址，或者程序本身就是个固定地址（无 `PIE`）。

## 三、核心利用流程
1. 检查保护（`Checksec`）： 确认 `NX` 为 `Disabled`，`PIE` 为 `No`。
2. 计算偏移量： 使用 `cyclic` 算出覆盖到返回地址的偏移量（如 `0x20 + 8 = 40`）。
3. 生成 `Shellcode`： 使用 `pwntools` 的 `asm`(`shellcraft.sh()`) 一键生成，或者用 `32` 位的 `23` 字节短 `shellcode`。
4. 构造 `Payload`： [填充垃圾数据] + [shellcode在内存中的地址] + [shellcode本体]。
5. 获取地址（难点）： 很多时候需要用 **gdb** 挂载调试，看看 `buffer` 在栈上的具体地址。如果开启了 `ASLR`，程序跑起来地址会变，所以通常要用 **gdb** 下断点，或者程序本身会打印出 `buffer` 的地址给你。

## 四、内存布局示意图（以 32 位为例）

```
+-------------------+  <-- 高地址
|   返回地址 (RET)   |  <-- 覆盖为 buffer 中 shellcode 的起始地址
+-------------------+
|     Saved EBP     |  <-- 被垃圾数据覆盖
+-------------------+
|    垃圾数据填充    |  <-- 填满偏移量
+-------------------+
|   shellcode 本体  |  <-- 写在缓冲区开头
+-------------------+
|   缓冲区起始地址   |  <-- 我们需要知道的绝对地址！
+-------------------+  <-- 低地址
```

## 五、常踩的坑（坑点排雷）
1. `NOP Sled`（滑板鞋）： 如果你在**gdb**里拿到的地址不是完全精准的，可以在 `shellcode` 前面塞满 `\x90`（NOP 指令），这样就算返回地址指偏了一点，程序也会顺着 `NOP` 滑到你的 `shellcode` 上。
2. `Bad chars`（坏字符）： 如果你是通过 `strcpy` 或 `gets` 读入数据的，你的 `shellcode` 里千万不能包含 `\x00`（空字符）或者 `\x0a`（换行符），否则会被截断。遇到这种情况，必须换一种读写函数，或者对 `shellcode` 进行编码。
