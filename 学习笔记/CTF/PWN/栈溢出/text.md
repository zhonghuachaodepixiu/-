# 栈溢出基础笔记

## 引言

栈溢出是Pwn方向比较基础的攻击手段，常用于未开启栈保护（Canary, NX）的程序。

要使用栈溢出，就需要先了解什么是“栈”。

## 一、什么是栈（逻辑数据结构层面）

程序运行时去申请一块空间，这个空间遵循“先进后出、后进先出”的原则，这个空间就被称之为栈。

* 如将1到5这5个数压入栈内，此时1处于栈底，5处于栈顶。

* 此时要取出1，就需要依次取出5、4、3、2。

栈的逻辑结构图：
```
       +--------+
  高   |   5    |  <-- 栈顶 (最后压入)
  ↑    +--------+
  |    |   4    |
  |    +--------+
 地    |   3    |
 址    +--------+
  |    |   2    |
  |    +--------+
  低   |   1    |  <-- 栈底 (最先压入)
       +--------+
```

## 二、什么是溢出

同样以上图为例，这是一个可存入5个数据的栈。

当我们在5上面再压入6时，栈布局会发生变化。

因为栈内已满，6会被填充在栈外（也就是向更高地址的方向溢出），覆盖掉原本不属于该栈区域（或相邻区域）的数据。

这种情况就被称为溢出。

溢出示意图：
```text
    +--------+
高  |   6    | <-- 溢出的数据，覆盖了更高地址的数据
↑   +--------+
|   |   5    |
|   +--------+
|   |   4    |
|   +--------+
地  |   3    |
址  +--------+
|   |   2    |
|   +--------+
低  |   1    | <-- 原本的栈底数据依旧在，未被挤压
    +--------+
```

## 三、结合真实内存：缓冲区与栈帧结构（核心！）

在真实的C语言程序中，所谓的“溢出”，通常是指缓冲区溢出（Buffer Overflow）。

我们经常使用数组来暂存数据，比如`char buf[10]`，这块连续的空间就是缓冲区。

当函数被调用时，会在物理内存的栈区开辟一块空间，这就是栈帧（`Stack Frame`）。

真实的函数栈帧布局从高地址向低地址看如下：
```text
+-------------------+ <-- 高地址
|      函数参数      |
+-------------------+
|   返回地址 (RET)   | <-- Pwn的终极目标！覆盖它就能劫持程序流
+-------------------+
|   Saved EBP (RBP) | <-- 覆盖它用于栈迁移
+-------------------+
|                   |
|   缓冲区 (buf)     | <-- 数据溢出的起点
|                   |
+-------------------+ <-- 低地址 (栈顶)
```

#### 漏洞产生原理：

程序中如果没有检查输入长度（如使用了`gets`、`strcpy` 等危险函数），当我们向 `buf` 写入超长数据时，多出的数据就会顺着内存的高地址方向覆盖，一路冲破缓冲区的边界，无情地将 `Saved EBP` 甚至返回地址覆盖掉。

## 四、Pwn中的终极利用

当函数执行完毕准备 `return` 时，它会去读取那个被我们覆盖过的“返回地址”。

如果我们将返回地址精准地覆盖成 `system("/bin/sh")` 的内存地址，程序就会乖乖交出控制权，为我们弹出一个 `Shell`！这就是栈溢出攻击的核心原理。
